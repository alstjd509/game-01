# 웹 미니게임 프로젝트 — 방향 결정

> 결정일: 2026-09-01 · 웹 미니게임 트랙 전체의 방향 정본. 아이디어 논의 → 컨셉 선정 → 기획 → **플레이 가능한 프로토타입**까지가 이 트랙의 작업 범위다.
> 논의 이력을 git으로 관리하기 위해 `game-01\docs\`에 둔다(2026-09-01 `C:\game` 루트에서 이동). 기존 Unity/스팀 프로젝트(다른 PC)와는 완전히 별개의 트랙.

## 1. 목표와 전략

- **목표**: 중독성·재미 위주의 미니게임을 짧은 공수로 만들어 출시까지 경험. 수익은 크지 않아도 실제로 시도.
- **전략**: 초기 1개 혹은 여러 개를 **웹에서** 만들며 설계·디자인·게임성 감각을 익힌다. 반응이 좋은 게임만 다음 단계(웹게임 포털 제출, 모바일 포팅)로 확장.
- **원칙**: 프로토타입을 굴려봐서 재미없으면 빠르게 폐기하고 다음 컨셉으로. 문서보다 손맛 검증이 우선.

## 2. 확정 결정

| 항목 | 결정 | 비고 |
|---|---|---|
| 플랫폼 | **웹 우선** | 학습·검증 목적. 반응 좋으면 포털·모바일 확장 |
| 개발 스택 | **JS + Phaser 3** (+ Vite) | 빌드 없이 브라우저 즉시 확인, 반복 속도 최우선 |
| 총 기간 | **1~2개월 / 1작품** | 본업·기존 프로젝트와 병행 |
| 규모 | 초소형은 지양 | 주당 시간은 변동적. 메타 성장(런 간 업그레이드) 정도의 볼륨은 포함 |
| 출시 채널 | **itch.io 먼저** | 심사 없음. 반응 좋으면 Poki·CrazyGames 등 포털 제출(광고 수익 셰어) |
| 장르 방향 | **아케이드 "한판 더" × 뱀서류·로그라이트** | 짧은 런 + 런 간 성장 조합이 교집합 |
| 아트 | 도트 툴 구매 예정 + 무료 에셋 + 초기 AI 활용 | 프로토 단계는 도형(그레이박스)으로 충분 |
| 산출물 범위 | 컨셉 → 미니 기획서 → **프로토타입 개발까지 이 트랙에서** | |

## 3. 제작 파이프라인 (1작품 기준)

1. **컨셉 논의·선정** — 후보 비교(§6) → 1개 선정, 문서에 기록
2. **미니 기획서** — 1~2페이지: 핵심 루프, 조작, 성장 축, 한 판 길이, 실패/재도전 흐름
3. **그레이박스 프로토** — 도형·색만으로 핵심 루프 구현. 목표: "한 판 더 하고 싶은가?"
4. **재미 판정** — 재미없으면 폐기 후 다음 컨셉 (매몰비용 무시). 재미있으면 계속
5. **폴리싱** — 아트·사운드·이펙트·손맛(juice), 메타 성장 붙이기
6. **itch.io 출시** — HTML5 zip 업로드, 피드백 수집
7. **회고 + 다음 결정** — 포털 제출 / 모바일 포팅 / 다음 게임

## 4. 툴·무료 리소스

### 도트 툴
- **Aseprite** (스팀 약 2만원) — 도트 표준. 구매 추천 ✔
- 무료 대안: LibreSprite(무료 포크), Piskel(브라우저)

### 무료 그래픽 에셋
- **Kenney.nl** — CC0(출처 표기 불필요), 양·품질 모두 최고. 프로토·출시 다 커버 가능
- **itch.io 무료 에셋** — 도트 게임용: `0x72 Dungeon Tileset`, `ansimuz`, `Cainos`, `Penzilla` 등 제작자 팩
- **OpenGameArt.org** — 방대하지만 품질 편차 큼. 라이선스 항목별 확인

### 사운드·음악
- 효과음 즉석 생성: **jsfxr / ChipTone** (브라우저에서 레트로 효과음 생성) — 프로토에 최적
- 효과음 라이브러리: Kenney Audio(CC0), freesound.org(라이선스 확인)
- 음악: Kevin MacLeod incompetech(CC-BY, 크레딧 표기), OpenGameArt 음악 섹션

### 폰트
- Google Fonts / 눈누(한글 무료 폰트 — 게임 임베드 허용 여부 개별 확인)

### AI 생성 주의점
- 일반 이미지 AI는 깔끔한 도트(픽셀 그리드 정렬)에 약함 → 도트 특화 툴(Retro Diffusion, PixelLab류)을 쓰거나, AI는 컨셉·목업용으로만 쓰고 실제 스프라이트는 에셋/직접 제작 권장

### 라이선스 원칙
- CC0 우선. CC-BY는 크레딧 표기 필수. 출시 전 사용 에셋 목록·라이선스를 문서로 남긴다.

## 5. 개발 환경 (착수 시)

- Phaser 3 (안정 버전) + Vite + vanilla JS, 게임별 폴더 분리 — **첫 게임: `C:\game\game-01\`**
- 각 게임 폴더의 `CLAUDE.md` = PC·세션 간 인수인계 문서(현재 상태 + 지침). 세션 종료 시 갱신
- 기획·회고 문서: 각 게임 폴더의 `docs\` 하위
- itch.io 배포: `vite build` 결과물 zip 업로드 (HTML5 게임으로 등록)
- 확장 경로: 포털(Poki/CrazyGames SDK 연동), 모바일(Capacitor 웹뷰 래핑)

## 6. 컨셉 후보 1차 (2026-09-01, 논의용 시드)

> 공통 전제: 한 판 1~5분, 즉시 재도전, 런 간 메타 성장 포함, 마우스(또는 단순 키) 조작 — 웹과 궁합 우선.
> 규모: S = 3~4주, M = 6~8주 (병행 기준 감).

| # | 가칭 | 한 줄 컨셉 | 핵심 중독 루프 | 조작 | 규모 |
|---|---|---|---|---|---|
| 1 | **스네이크 서바이버** | 스네이크 × 뱀서 — 먹은 것이 몸 파츠(무기)가 되어 자동 공격 | 몸이 길수록 강해지지만 조작은 어려워짐(리스크=파워) → 욕심과 생존의 줄다리기 | 방향키/마우스 | M |
| 2 | **원버튼 미니뱀서** | 마우스만 따라다니는 3분 압축 뱀서 | 웨이브 생존 → 레벨업 3택 → 빌드 완성 욕구 → "이번 빌드로 한 판 더" | 마우스 이동만 | M− |
| 3 | **머지 디펜스** | 수박게임식 드롭·합치기로 유닛을 만들고, 그 유닛이 웨이브를 방어 | 큰 유닛 합성 쾌감 + 무너지기 직전 역전 → 한 판 더 | 마우스 드롭 | M |
| 4 | **딥 다이버** | 한 런 1~3분 아래로 채굴, 연료 소진 전 귀환 → 장비 업글 → 더 깊이 | "조금만 더 깊이" 욕심 vs 귀환 타이밍 + 메타 성장 | 방향키 | M |
| 5 | **탄막 회피 러너** | 공격 없이 회피만. 생존 시간이 곧 점수·재화 | 죽는 순간 원인이 명확 → 즉시 재도전, 재화로 대시·자석 등 업글 | 마우스/방향키 | S+ |
| 6 | **궤도 슈터** | 행성 주위를 자동 공전, 클릭으로 방향 반전·사격하며 적 요격 | 단순 조작 대비 깊은 타이밍 숙련 + 업그레이드 트리 | 클릭만 | S+ |

### 선정 기준(논의 시 사용)
1. 30초 안에 재미를 설명할 수 있는가 (itch.io 썸네일·GIF 한 장으로 전달되는가)
2. 그레이박스만으로 재미 검증이 가능한가
3. 1~2개월(변동 시간) 안에 폴리싱까지 가능한가
4. 죽었을 때 "내 탓"이라 느껴지는가 (한판 더의 핵심)
5. 런 간 성장이 자연스럽게 붙는가
